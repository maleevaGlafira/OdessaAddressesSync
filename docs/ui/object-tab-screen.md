# UI: экран вкладки объекта

Единый шаблон экрана для вкладок:
- Типы улиц
- Улицы
- Дома

Структура и поведение одинаковые.  
Отличаются только название объекта, файл и набор полей.

## Общая структура

- Шапка приложения
- Вкладки: Типы улиц | Улицы | Дома | Журнал загрузок
- Переключатель режимов: **Просмотр** | **Загрузка**
- По умолчанию: режим **Просмотр**

Неактивные / нереализованные вкладки показывают заглушку «В разработке».

---

## Режим «Просмотр»

Главная задача экрана — показать **сведение** двух таблиц:
- основная таблица Firebird
- входная таблица загруженных данных

Каждая строка таблицы = одна пара объектов (или неполная пара).

### Логика отображения строки

- Есть объект в основной таблице и есть связанный во входной → показываем оба
- Есть объект только в основной → правая часть пустая
- Есть объект только во входной → левая часть пустая, правая заполнена

Структура таблицы для Типы улиц /view-columns/street-types.md

Вкладки  **Улицы**  **Дома**  -заглушка на данном этапе

## Поиск и фильтрация

Под заголовками столбцов таблицы располагается строка фильтров.
Каждому столбцу соответствует отдельное поле ввода.

### Правила поиска

- Пользователь может заполнить одно или несколько полей фильтра.
- Поиск выполняется по нажатию Enter в любом поле фильтра
  или кнопки «Поиск», расположенной справа от таблицы.
- Для каждого заполненного поля выполняется поиск по частичному
  совпадению, аналогичному SQL `LIKE '%значение%'`.
- Если заполнено несколько полей, результаты должны одновременно
  соответствовать всем заданным условиям (логическое AND).
- Пустые поля фильтра не участвуют в поиске.
- Поиск выполняется по отображаемым данным соответствующих столбцов.

### Сброс фильтра

Кнопка «Сбросить» очищает все поля фильтра и возвращает
полный список записей с учетом текущего режима отображения.

---

### Элементы управления

-Над таблицей расположены основные действия:

- **«Обновить»** — повторно загружает данные текущего объекта из базы данных.
- **«Добавить»** — добавляет новый объект. На текущем этапе кнопка отображается как недоступная и зарезервирована для будущей реализации.

В последнем столбце каждой строки расположены действия над соответствующей записью:

- **«Редактировать»** —  иконка открывает запись для изменения. На текущем этапе действие недоступно.
- **«Удалить»** — иконка удаляет запись после подтверждения пользователем. На текущем этапе действие недоступно.

Для недоступных действий используются неактивные иконки. При наведении отображается подсказка о том, что функция находится в разработке.

В нижней части таблицы отображаются:

- **«Всего: N»** — общее количество записей.
- **Пагинация** — переход между страницами таблицы.

Счётчик и пагинация закреплены в нижней части рабочей области таблицы.


## Режим «Загрузка»

Загрузка CSV-файла соответствующего типа.

### Общие требования к файлу
- Формат: CSV
- Разделитель: `;`
- Кодировка: UTF-8
- Первая строка — заголовки колонок

### Файлы и обязательные колонки

**Типы улиц** → `s_vidul.csv`
- `код типу вулиці`
- `назва типу вулиці`
- `скорочена назва типу вулиці`

**Улицы** → `s_ulic.csv`
- `код вулиці`
- `код типу вулиці`
- `скорочена назва типу вулиці`
- `назва вулиці`

**Дома** → `s_dom.csv`
- `код будинку`
- `код вулиці`
- `номер будинку`
- `корпус`

### Состояния загрузки (одинаковые для всех)

1. **Файл не выбран**
   - Зона выбора файла
   -
   - Кнопка «Проверить файл» — неактивна

2. **Файл выбран**
   - Имя файла + размер
   - Кнопка «Удалить»
   - Кнопка «Проверить файл» — активна

3. **Ошибка формата / колонок**
   - Красный блок с описанием
   - Кнопка «Загрузить другой файл»

4. **Есть ошибки в данных**
   - Сводка: Всего / Ошибок / Без ошибок
   - Таблица ошибочных строк (№ строки + поля объекта + текст ошибки)
   - Пагинация
   - Кнопки: «Отменить» | «Подтвердить загрузку»

5. **Ошибок нет**
   - Зелёный блок: «Файл проверен. Строк: N. Ошибок нет.»
   - Кнопки: «Отменить» | «Подтвердить и загрузить»

### После успешной загрузки
- Данные записываются в базу
- Запись в журнал загрузок

6. После загрузки в  _input отобразить та что влили и  ошибкм
 Если есть новые запси то кнопка  синхронизация
 По кнопке синхронизовать делаем синхронизацию _input и внешней таблицей
 Обнавляем таблицы и переходим в режим просмотра

### Проверка файла

После выбора CSV пользователь запускает проверку кнопкой «Проверить файл».

Проверка выполняется в два этапа:

1. **Проверка формата файла**
   - наличие обязательных колонок;
   - соответствие типов данных ожидаемым типам;
   - соответствие структуры файла требованиям проекта.
Если ошибки в пункте 1 то отображается блок  **Ошибка формата / колонок** 

2. **Проверка данных**
   - выполняются правила, определённые для соответствующего типа объекта в `rules.md`;
   - для каждой строки определяется результат проверки;
   - ошибки сохраняются и отображаются пользователю.
Если ошики в пункте 2 отображается таблица с неправильными данными в первой колонке указывается номер строки с ошибкой   

**Источник правил:** для каждого типа обьектов в  `docs/rules.md`.

## Поведение

- Переключатель режимов общий для всех вкладок.
- «Отменить» возвращает к состоянию «файл не выбран».
- Логика проверки и отображения ошибок одинаковая.
- Меняются только поля и правила валидации конкретного типа объекта.
