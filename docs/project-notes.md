## Загрузка входных данных

- Получить CSV-файлы.
- Переместить исходный файл в `data/row`.
- Прочитать файл.
- Загрузить данные во временную таблицу.
- Сравнить с данными Firebird.

## Сравнение данных

Нужно определить:
- какие поля сравниваются;
- как определять одинаковые объекты;
- как показывать расхождения;
- какие данные пользователь может исправлять.

## Обработка расхождений

Возможная схема:

1. Показать пользователю только расхождения.
2. Пользователь проверяет данные.
3. Пользователь при необходимости исправляет данные.
4. Сохранить результат проверки.
5. Повторно проверить данные перед записью в БД.

## Сведение объектов

Для новых объектов возможно потребуется определить соответствие
с уже существующими объектами Firebird.

Нужно отдельно продумать:
- как искать соответствие;
- что делать, если найдено несколько вариантов;
- что делать, если соответствие не найдено;
- какие действия выполняет пользователь.

## Дома

Для `s_dom.cvs` сведение с существующими объектами не требуется.

Данные домов должны быть загружены в Firebird отдельно.

## Загрузка входных файлов

Входные данные из внешних файлов не должны сразу заменять текущие данные в таблицах `S_INPUT_*`.

Предполагаемый процесс загрузки:

1. Получить входной файл.
2. Определить тип файла (`s_vidul.cvs`, `s_ulic.cvs`, `s_dom.cvs`).
3. Проверить структуру файла:

   * наличие ожидаемых полей;
   * соответствие формату;
   * корректность данных.
4. Загрузить файл во временную область / новую версию входных данных.
5. Проверить загруженные данные:

   * структуру;
   * количество записей;
   * основные ограничения и зависимости.
6. Если проверка успешна, сделать новую загрузку текущей.
7. Если проверка не пройдена, не заменять текущие входные данные и показать пользователю ошибку.

### Таблицы входных данных

Для хранения данных внешнего источника предполагается использовать отдельные таблицы Firebird:

* `S_INPUT_VIDUL` — типы улиц;
* `S_INPUT_ULIC` — улицы;
* `S_INPUT_DOM` — дома.

Данные этих таблиц являются копией данных внешнего источника и используются как промежуточный слой перед дальнейшей обработкой.

Наличие одинаковых названий объектов (`S_VIDUL`, `S_ULIC` и `S_INPUT_*`) не означает, что данные в них одинаковые. `S_INPUT_*` хранит данные внешнего источника, а основные таблицы Firebird содержат существующие данные адресного плана.

### Учёт загрузок

Предполагается отдельная таблица для регистрации загрузок входных файлов.

Она должна позволять определить:

* какой файл был загружен;
* когда была выполнена загрузка;
* к какому типу данных относится загрузка;
* результат проверки;
* какая загрузка является текущей.

Точная структура таблицы загрузок пока не определена.
