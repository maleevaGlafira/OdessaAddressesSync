## Загрузка входных файлов

Файл  → файл в `data/row` → проверка структуры и данных → временная таблица для `S_INPUT_ULIC` / `S_DOM_EXT` → проверка → подтверждение пользователя → обновление `S_INPUT_*`.

Для `S_INPUT_VIDUL` временная таблица не требуется: типов улиц мало, данные можно проверить и обновить напрямую.

`S_INPUT_ULIC` и `S_DOM_EXT` — постоянные таблицы входных данных. Для определения новых и изменённых объектов используется ID из внешнего источника.

`S_DOM_EXT` — единственная таблица домов в базе. Внешний ID дома должен сохраняться и использоваться для дальнейшей связи с объектами базы.

### Учёт загрузок

`S_INPUT_LOAD` хранит только информацию о загрузках: имя файла, тип данных и дату/время загрузки. Сами файлы в этой таблице не хранятся.

## Сравнение данных

Нужно определить:
- какие поля сравниваются;
- как определять одинаковые объекты;
- как показывать расхождения;
- какие данные пользователь может исправлять.

## Обработка расхождений

Возможная схема:

1. Показать пользователю только расхождения.
2. Пользователь проверяет данные.
3. Пользователь при необходимости исправляет данные.
4. Сохранить результат проверки.
5. Повторно проверить данные перед записью в БД.
