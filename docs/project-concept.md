## Идеи проэкта
получить входные CSV;
загрузить их во временные/входные таблицы;
сравнить с Firebird;
определить различия;
предоставить пользователю возможность проверить/исправить данные;
после подтверждения сохранить изменения;
для новых объектов определить соответствия с существующими;
отдельно обрабатывать несопоставленные объекты;
выполнить проверку перед записью в основную БД.

## Цепочка движения данных

1 получения данных из входящи файлов cvs
2 файл переместить в data/row
3 прочитать файл
4 прочитать существующую информацию если есть _описать сделаьб таблицы под входящую информацию_
5 сравнить данные из базы и из файла показать не сходящтеся _описать формат отображения несхождений и поля куда положить правильные данные после коррестирвки пользователем_
в интрфейсе только не сходящиеся строки \*_описать формат отображения несхождений и действия пользователя для сохранения правильной инфы_
и в data/proccessed все строки отмечая не сходящиеся в начале
6.-1 если из data/proccessed данные нужно провериить
6 после подтверждения пользователя загрузить данные из интерфейса либо из data/proccessed в базу
7 попытка свдения с существующими обьектами в базе
8 все что не получилось показать
в интерфейсе либо в _описать интерфейс и дейсвия пользоваителя для исправления_
data/proccessed _описать формат отображения несхождений и поля куда положить правильные данные после коррестирвки пользователем_
9 Проверить данные от пользователя
10 Созранить данные в базу

Если данные не нужно сводить с существующими то пункты 7-10 не делаем - для houses сводить не нужно
