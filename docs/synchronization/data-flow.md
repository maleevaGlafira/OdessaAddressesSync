# Data Flow

## Назначение

Документ описывает текущий поток обработки данных при синхронизации
внешних CSV-файлов с данными Firebird.

На текущем этапе рассматривается синхронизация типов улиц и улиц.

## Текущий поток данных

```text
s_vidul.csv ──┐
              ├─→ входные данные → сравнение с Firebird → результат сравнения
s_ulic.csv ───┘

Firebird S_VIDUL ──┐
                   ├─→ сравнение
Firebird S_ULIC ───┘

s_dom.csv → S_DOM_EXT → Firebird
```
 
## Этапы
```text
Получить внешние CSV-файлы.
Прочитать данные CSV.
Прочитать соответствующие данные из Firebird.
Подготовить данные для сравнения.
Сравнить данные внешнего источника с Firebird.
Определить различия:
новые объекты;
изменённые объекты;
отсутствующие объекты;
объекты, для которых требуется дополнительная проверка.
Сформировать результат сравнения для дальнейшей обработки.
```

# Объекты текущей синхронизации

| Внешний источник | таблица  Firebird | Синхронизация | Залить вбазу |
|-----------------|--------------------|---------------|--------------|
| s_vidul.csv     |	S_VIDUL	           | Да            | Да           |
| s_ulic.csv	  |   S_ULIC	       | Да            | Да           |
| s_dom.csv	      |   —                | Нет           | Да           |
| Районы  	      | S_RAYON   	       | Нет           | Нет          |

# Что пока не определено 

Соответствия между идентификаторами внешнего источника и идентификаторами
Firebird пока не определены.

Правила определения соответствий, обработки новых объектов и записи
изменений в основную БД будут определены на следующих этапах проекта.

# Детальный Поток обработки внешних адресных данных


## 1. Обработка типов улиц

Типы улиц загружаются из файла s_vidul.csv.
### Типы улиц — `s_vidul.csv`

1. **Прочитать данные из CSV.**
   Загрузить данные из `s_vidul.csv`, содержащие внешний код типа улицы, полное и сокращённое название.
2. **Проверить корректность идентификаторов и названий.**
   Проверить наличие обязательных полей, корректность внешних кодов и отсутствие дублирующихся идентификаторов.

3. **После успешного завершения загрузки в S_INPUT_LOAD сохраняются:**

    - тип загруженных данных;
    - имя исходного файла;
    - дата и время загрузки.

    Получит идтификатор загрузки S_INPUT_LOAD.ID

4. **Сопоставить типы улиц по внешним идентификаторам.**
   Если поле `код типу вулиці` в файле и поле  EXT_ID  в `s_vidul  в базе одинаковые то сравнить даные других полей 
   Если данные не совпадают то обновить данные  сбросит поле FK_ID_VIDUL
   если  даных с таким `код типу вулиці` в базе нет то вставить
   если данные есть и совпадают то оставить как есть
   
5. **Перенести подтверждённые данные в `S_INPUT_VIDUL`.**
   После проверки и подтверждения данные из CSV сохраняются в постоянной входной таблице `S_INPUT_VIDUL`. Только измененные и новые данные

   Для каждой записи сохраняются:

   * `EXT_ID` — внешний код типа улицы;
   * `NAME` — полное название;
   * `SHORT_NAME` — сокращённое название.

   * `LOAD.ID ` - S_INPUT_LOAD.ID из шага 3

   После загрузки запись может быть использована для сопоставления с существующим справочником `S_VIDUL`.

5. **Сопоставить входные типы улиц с `S_VIDUL`.**
   Заполняем  пустые поля `S_VIDUL` если данные уже есть не изменяем
   Сопоставление выполняется по правилам из [`rules.md`](rules.md)  

   
*Пользовательский интерфейс для указания соответствий и  для добавления улиц в ручную*

   Таким образом, связь типа внешнего источника с существующим типом Firebird имеет вид:

   `S_INPUT_VIDUL.EXT_ID → S_INPUT_ULIC.EXT_TYPE_ID`

   и после сопоставления:

   `S_INPUT_VIDUL.FK_ID_VIDUL → S_VIDUL.ID`

   Подробные правила сопоставления описаны в [`rules.md`](rules.md).


Для типов улиц отдельная временная таблица не используется.

## 2 Обработка улиц

Улицы загружаются из файла `s_ulic.csv`.

**Структура таблицы ошыбочных записей**
`код вулиці`
`код типу вулиці` 
`назва вулиці`
`№ строки в исходном файле`
`Причина ошибки`

**Соответсвие между таблицей 'S_INPUT_ULIC' и  полями файла `s_ulic.csv**

EXT_ID -`код вулиці`
EXT_TYPE_ID -`код типу вулиці` 
NAME `назва вулиці`     

1. **Прочитать данные из CSV.**

2. **Проверить структуру и типы полей файла.**

   До загрузки проверить:

   * наличие всех обязательных полей;
   * соответствие типов данных полям таблицы;
   * корректность числовых идентификаторов;
   * отсутствие строковых значений в числовых полях и наоборот;
   * корректность и нормализацию текстовых значений.

   Если структура файла или типы данных некорректны — загрузку остановить и сообщить пользователю об ошибке.

3. **Загрузить во временную таблицу `TMP_INPUT_ULIC` только новые и изменённые улицы.**

   Идентификатор `код вулиці` из файла соответствует `S_INPUT_ULIC.EXT_ID`.

   Для каждой записи:

   * если `EXT_ID` отсутствует в `S_INPUT_ULIC` — запись является новой и загружается;
   * если `EXT_ID` существует, сравнить остальные поля указанные в соответствии после нормализации текстовых значений;
   * если хотя бы одно значение изменилось — запись считается изменённой и загружается;
   * если все значения совпадают — запись не загружается во временную таблицу;
   

4. **Проверить наличие соответствующих типов улиц.**

   Для каждой загружаемой улицы проверить, что её `EXT_TYPE_ID` соответствует записи в `S_INPUT_VIDUL` и для этого типа определено соответствие с `S_VIDUL`.

   Правила проверки типов описаны в [`rules.md`](rules.md), раздел **«2.1. Определение типа улицы»**.

   Если тип улицы не определён — эту запись поместить  таблицу ошибочных строк. убрать из TMP_INPUT_ULIC "

6. **После успешного завершения загрузки в S_INPUT_LOAD сохраняются:**

    - тип загруженных данных;
    - имя исходного файла;
    - дата и время загрузки.

    Получит идтификатор загрузки S_INPUT_LOAD.ID

5. **После успешного прохождения всех проверок перенести данные в `S_INPUT_ULIC`.**

   Если все проверки выполнены успешно, новые и изменённые записи переносятся из `TMP_INPUT_ULIC` в `S_INPUT_ULIC`. указывая LOAD_ID из шага 6
   В измененных улицах нужно сбросить поля FK_ID_ULIC MATCH_STATUS M_CANDIDATES

7. **Очистить `TMP_INPUT_ULIC`.**

   После успешного переноса временная таблица очищается.

8. **Вывети таблицу ошибочных записей или сообщить что таких нет и колво обновленных добавленных записей**

   **Сопоставление загруженных улиц с основной таблицей `S_ULIC` на этом этапе не выполняется.**

9. **Выполнить сведение улиц между таблицами    `S_ULIC` и  `S_INPUT_ULIC`**
    Заполнить таблицу  `S_INPUT_ULIC` поля  FK_ID_ULIC MATCH_STATUS M_CANDIDATES согласно    правилаям в [`rules.md`](rules.md) ### 2. Сопоставление улиц — S_INPUT_ULIC

*Пользовательский интерфейс для указания соответствий и  для добавления улиц в ручную*

Внешний идентификатор улицы используется для её сопоставления
между загрузками.

## 3. Обработка домов

Дома загружаются из файла `s_dom.csv`.

**Соответствие полей `S_DOM_EXT` и `s_dom.csv`:**

| `S_DOM_EXT`     | Поле `s_dom.csv` |
| --------------- | ---------------- |
| `EXT_ID`        | `код будинку`    |
| `EXT_STREET_ID` | `код вулиці`     |
| `HOUSE_NUMBER`  | `номер будинку`  |
| `CORPUS`        | `корпус`         |

Структура таблицы `S_DOM_EXT` описана в [`firebird.md`](../database-model/firebird.md).
Типы и состав полей входного файла описаны в [`inputCsv.md`](../database-model/inputCsv.md).

1. **Прочитать данные из CSV.**

2. **Проверить структуру и типы полей файла.**

   Проверить наличие всех необходимых полей и соответствие типов данных требованиям, указанным в [`inputCsv.md`](../database-model/inputCsv.md).

   Если структура файла или типы полей не соответствуют требованиям, загрузку остановить. Данные во временную таблицу не загружать.

3. **Определить новые и изменённые дома.**

   Идентификатор `код будинку` из файла соответствует `S_DOM_EXT.EXT_ID`.

   Для каждой записи:

   * если `EXT_ID` отсутствует в `S_DOM_EXT` — дом является новым;
   * если `EXT_ID` существует, сравнить остальные поля с существующей записью;
   * если данные изменились — дом считается изменённым;
   * если данные полностью совпадают — запись не загружать.

   В `TMP_INPUT_DOM` загружаются только новые и изменённые дома.

4. **Проверить обязательные значения.**

   Для каждой загружаемой записи проверить заполненность:

   * `код будинку`;
   * `код вулиці`;
   * `номер будинку`.

   Если хотя бы одно из этих полей не заполнено, запись не загружать в `TMP_INPUT_DOM`, а внести в таблицу ошибок.

5. **Проверить соответствующую улицу.**

   Значение `код вулиці` (`EXT_STREET_ID`) должно существовать в `S_INPUT_ULIC.EXT_ID`.

   Если соответствующая улица отсутствует, запись внести в таблицу ошибок и не переносить в `S_DOM_EXT`.

6. **Перенести данные в `S_DOM_EXT`.**

   Если все проверки успешно пройдены, новые и изменённые записи из `TMP_INPUT_DOM` перенести в `S_DOM_EXT`.

   Дома не сопоставляются с существующими таблицами домов Firebird.

7. **Обработать ошибки.**

   Для каждой записи с ошибкой сохранить исходные поля `s_dom.csv` и дополнительные поля:

   * `ROW_NUMBER` — номер строки исходного файла;
   * `ERROR_REASON` — причина ошибки.

   Таблица ошибок предоставляется пользователю. Интерфейс пока не определён.

8. **Очистить `TMP_INPUT_DOM`.**

   После завершения обработки временная таблица очищается.

*Пользовательский интерфейс для указания соответствий и  для добавления домов в ручную и отображения таблицы ошибок*

## 5. Журнал загрузок

После успешного завершения загрузки в S_INPUT_LOAD сохраняются:

- тип загруженных данных;
- имя исходного файла;
- дата и время загрузки.

Содержимое CSV-файлов и большие объёмы исходных данных в журнале
не хранятся.



## 6. Границы текущей реализации

На текущем этапе:

- автоматическое обновление существующих таблиц адресов не выполняется;
- автоматическое сопоставление домов с существующими домами не выполняется;
- история изменений отдельных записей не хранится;
- журнал загрузок содержит только метаданные файлов.
