
## Правила сопоставления

### 1. Сопоставление типов улиц — S_INPUT_VIDUL

1. Нормализовать `S_INPUT_VIDUL.SHORT_NAME`.
2. Сравнить с нормализованным `S_VIDUL.NAME_UA`.
3. Если найдено одно соответствие, записать `S_VIDUL.ID` в `FK_ID_VIDUL`.
4. Если соответствие не найдено или найдено несколько вариантов, оставить `FK_ID_VIDUL` пустым для дополнительной проверки.

### 2. Сопоставление улиц — S_INPUT_ULIC

#### 2.1. Определение типа улицы

1. Найти соответствующий тип улицы по `S_INPUT_ULIC.EXT_TYPE_ID` через `S_INPUT_VIDUL.FK_ID_VIDUL`.
2. Если тип улицы не сопоставлен, установить статус `TYPE_NOT_MATCHED` и не выполнять поиск улицы.

#### 2.2. Поиск соответствия

1. Нормализовать `S_INPUT_ULIC.NAME`.
2. Определить основное название и, если оно есть, старое название в скобках.
3. Искать соответствие среди `S_ULIC.NAME_UA` только для улиц подходящего типа.

**Приоритет поиска:**

1. Сначала проверить полное название, включая название в скобках.
2. Если найдено одно соответствие, записать `S_ULIC.ID` в `FK_ID_ULIC` и установить `MATCHED`. Поиск по отдельным названиям не выполнять.
3. Если полное соответствие не найдено, проверить основное название и название в скобках по отдельности.
4. Объединить найденные варианты и исключить дубликаты.
5. Если найден один кандидат, проверить, не связан ли он уже с другой входной записью.
6. Если найдено несколько кандидатов, установить `MULTIPLE`.
7. Если кандидатов нет, установить `NOT_FOUND`.

#### 2.3. Проверка кандидата

- Если единственный кандидат ещё не связан с другой входной записью, записать его ID в `FK_ID_ULIC` и установить `MATCHED`.
- Если кандидат уже связан с другой входной записью, установить `ALREADY_LINKED`.
- Если автоматическое сопоставление невозможно по другим причинам и требуется ручная проверка, установить `REVIEW`.

### 3. Статусы сопоставления — MATCH_STATUS

| Статус | Описание |
|---|---|
| `MATCHED` | Найдено однозначное соответствие. `FK_ID_ULIC` заполнен. |
| `NOT_FOUND` | Подходящая улица не найдена ни по полному, ни по отдельным названиям. |
| `MULTIPLE` | Найдено несколько подходящих кандидатов. Требуется ручной выбор. |
| `ALREADY_LINKED` | Единственный кандидат уже связан с другой входной записью. |
| `TYPE_NOT_MATCHED` | Тип улицы не сопоставлен, поэтому поиск улицы не выполнялся. |
| `REVIEW` | Требуется ручная проверка по другой причине, не охваченной остальными статусами. |

### 4. Результат сопоставления

- `FK_ID_ULIC` заполняется только при статусе `MATCHED`.
- При остальных статусах `FK_ID_ULIC` остаётся пустым.
- `M_CANDIDATES` содержит список найденных кандидатов, если их несколько или требуется дополнительная проверка.
- Статус и список кандидатов обновляются при повторном выполнении сопоставления.
